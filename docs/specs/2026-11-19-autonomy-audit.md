# PROTO 自主性审查与产品化闭环加固（M61）

## 1. 目标

本轮审查回答一个标准：**不管人设是什么，PROTO 都应像该领域的高级专家一样，持续学习、提出值得做的任务、设计、实现、验证并交付到“只欠主人授权/资源”的成熟度。**

具体目标：

1. 补上“想法 → 目标树 → 交付阶梯”的断点，让自主目标不是一次性学习笔记。
2. 让本地产品验证真的能作用于项目工作区，而不是只能在临时目录跑孤立 Python。
3. 让验收标准一经生成不可漂移，独立验证能看到最终产物原文。
4. 修正自主任务预算分账、失败文案、方法重复发明等已知易用性/可靠性问题。
5. 继续遵守 L1 边界：主人优先级、预算、审计、沙盒和审批优先于自主性。

## 2. 非目标

- 不自动提交 App Store、发邮件、付费或使用主人账号；这些只能进入“待主人提供/一键继续”清单。
- 不绕过 owner-only、不可逆与可见写审批。
- 不引入云服务、多租户或新的运行时依赖。
- 不承诺无 LLM 时完成同等质量的设计开发；离线状态必须诚实降级。

## 3. 审查结论

| 角度 | 发现 | 影响 |
|---|---|---|
| 架构 | `MetacogScheduler` 会触发 `goal_generation`，但运行时未注册回调 | “定时目标生成”只是事件名，目标树吃完后自主性退化为学习笔记 |
| 功能 | 长期目标分解提示要求 3–4 阶段，实现截断为 3 | “就绪交付”阶段经常被丢弃，缺少成熟产品交接面 |
| 功能 | `run_python` 在临时目录执行，不能直接运行项目测试/编译 | 设计与实现有了，本地验证链断了 |
| 质量 | 生成的验收标准没有写回 GoalNode | 下一轮可重新生成不同标准，违背“验收不可自我修改” |
| 质量 | 独立验证只看 `write_file/edit_file` 参数，不读最终文件 | 编辑后的真实产物可能被误判为证据缺失 |
| 预算 | 自主生成目标执行仍默认消耗 owner 池 | 自主/主人任务分账失真，owner 池被自主目标挤占 |
| 易用性 | `force_act` 返回执行 dict 时 UI 显示 `[object Object]`；失败原因笼统 | 主人无法判断该充值、配置 LLM、给输入还是等下一拍 |
| 学习 | 方法库仅同名去重 | `repo_pattern_mine/mining` 这类近似名重复入库，浪费快模型调用 |
| 学习 | 记忆检索没有强化被检索项 | “检索练习效应”写了设计但没执行 |

## 4. 用户流程

### 4.1 空闲时的专家闭环

1. 心跳推进欲望、情绪、记忆与预测复核。
2. 无可执行目标且张力/欲望越阈，或 4 小时节奏到期时，GoalForge 启动：
   - 输入：人设、主人优先级、审美锚点、活跃目标、近期反思、世界模型事实。
   - 输出：3–5 个候选想法，每个必须包含本机可验证验收。
   - 本地评分淘汰：主人对齐、人设契合、新颖性、可行性、验收质量。
3. 幸存想法写入 `GoalTree`（`source=self`），并分解为：设计规格 → 功能实现 → 本地验证 → 就绪交付。
4. 下一拍选择该目标执行；每阶段有项目目录、验收、接力日志和独立验证。
5. 全部本地阶段 verified 后，长期目标完成；GoalForge 可继续提出下一个想法。

### 4.2 本地验证与交付

1. Python 测试/脚本在工作区根执行，可直接 import/read 项目文件。
2. 沙盒后端可用时开放 `run_command`：无 shell、命令白名单、参数数组、cwd 限制在工作区内、写遏制与禁网沿用平台沙盒。
3. 典型链路：`write_file` 实现 → `run_command`/`run_python` 测试或编译 → 失败反馈修正 → 独立验证读取最终产物 → `DELIVERY.md`/就绪报告。
4. 缺账号、证书、设备、商店资料时，不中断整链；Agent 完成全部本机可完成项，报告“待主人提供”和“一键继续”的具体动作。

## 5. 数据与状态模型

### GoalForge

`store["goal_forge"]["main"]`：

```json
{
  "last_attempt_ts": 0.0,
  "last_created_ts": 0.0,
  "attempts": 0,
  "created": 0,
  "last_error": ""
}
```

目标仍以 `GoalTree` 为唯一权威；GoalForge 不另建队列。

### GoalNode

- `acceptance`：首次生成后立即持久化；后续执行只读，不允许 Agent 自我改标准。
- `source=self`：执行预算走 `self_initiated`；owner 播种目标走 `owner_tasks`。
- `fail_streak/approach_resets`：沿用现有换打法机制。

### 交付阶梯

子目标最多接受模型输出的 4 个阶段；若无“就绪交付”阶段则追加固定本地阶段：

“整理就绪交付包：README、运行/测试证据、待主人提供事项、一键继续指引。”

## 6. 关键交互与错误处理

- GoalForge 解析失败：审计 `goal_forge_failed`，返回空，不阻塞学习回退。
- 候选无本机验收或与活跃目标高度重复：本地淘汰，不入树。
- 自主预算不足：记录 `budget_floor_wait`，等充值/次日重置，不伪造执行。
- `run_command` 后端不可用：返回 `execution_disabled`，不降级为 shell。
- 命令/参数越界：返回可纠错错误，Agentic 循环可换方法，不造成任务级崩溃。
- `force_act`：执行对象转为人类可读摘要；未行动时区分 LLM 未接、预算不足、连败保护与确实无产出。

## 7. 安全模型

- 沙盒命令不允许 shell 字符串，只允许数组 argv。
- 工具注册表仍决定最低风险级别；模型声明只能加严。
- `runsc/sandbox-exec` 下写遏制与禁网；未隔离后端必须审批且 owner-only。
- 沙盒 profile 显式拒绝读取 agent 私钥、环境凭证和持久化内部状态目录，防止“run Python 读 owner.key”的横向越权。
- 外部网页仍为 CONTENT 通道，只作学习素材，不进入反馈归因。

# ADR 0015：将网络超时分类与本地执行日志分开

- 状态：已采纳（2026-11-22）
- 契约与验收：[模型超时恢复与本地执行日志](../DESIGN.md#execution-diagnostics)

## 背景

短请求可用不代表长期自主任务不会超时。Python 3.9 的 `socket.timeout` 和 `TimeoutError` 并非同一类型；漏判读超时会让模型组放弃切换，并使原 Run 停在人工续作。现有实时活动为内存短窗口，既不能跨重启关联，也不足以区分服务端失败、本地拦截和安全续作。

## 决策

- 在模型故障分类边界保留可枚举原因、HTTP 状态和异常类型，统一直接或包装的网络超时。复用既有切换、同源退避及持久续作，不扩大重试范围或吞掉请求拒绝。
- 用本机滚动 JSONL 记录关联的模型尝试和已提交 Run 结果；只写受控的元数据，不采集请求、文件及输出内容。Web 和 CLI 在实例锁内启用，日志与审计链、实时活动和恢复状态分别维护。日志失败不得阻断业务。

## 未采纳

- 全量请求转储、记录原始异常文本、数据库加日志表或依赖外部日志服务：前两项容易泄露隐私，后两项超出单机排障需要。
- 对所有错误自动换路、加大尝试上限或定时测所有候选：会掩盖真实配置问题、浪费额度，也会触发更多限流。

# ADR 0002：GoalForge 与本地验证能力

> **决策记录，保留采纳理由。** 当前累计方案及实现边界已归并至 [PROTO 总设计](../DESIGN.md)；本记录不是另一份当前总设计，原决策状态保留。

- 状态：接受
- 日期：2026-11-19

## 背景

PROTO 已有目标树、Agentic 循环和质量门，但“定时目标生成”没有运行时接线；目标耗尽后只生成学习笔记。`run_python` 在临时目录运行，无法验证项目产物；交付阶段在目标分解中被截断。用户核心设计要求自主 Agent 能持续提出高质量任务并完成到本机可验证的成熟度。

## 决策

1. **新增 GoalForge，而不另建目标队列。** 它负责内外部信号到候选想法的生成与本地淘汰；唯一持久权威仍是 `GoalTree`。
2. **自主目标必须携带本机可验证验收。** 验收首次生成即写回 GoalNode，执行者不能后续调整标准。
3. **交付阶梯是一等结构。** 分解必须落到设计、实现、本地验证、就绪交付。
4. **扩展本地执行能力，但不放弃沙盒。** `run_python` 以项目工作区为 cwd；`run_command` 仅在平台隔离后端下自动放行，使用数组 argv、命令白名单、工作区 cwd、写遏制和禁网。
5. **自主目标用自主预算。** `source=self` 的 Agentic 链走 `self_initiated`；owner 播种目标继续走 `owner_tasks`。

## 后果

- 空闲自主性从“读一个仓库写笔记”升级为“生成可交付产品目标并推进完整本地闭环”。
- Agent 可以运行项目测试/编译，但不能直接完成需要主人账号、设备、付费或发布权限的步骤。
- 平台沙盒是新增命令能力的前提；无隔离后端仍失败关闭或进入人工审批。
- 需要持续维护命令白名单和沙盒例外，避免以“本地验证”名义扩大权限。

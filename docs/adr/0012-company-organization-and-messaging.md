# ADR 0012：公司组织与定向通信

- 日期：2026-11-22
- 状态：采纳

## 背景

舰队是 Agent 的生命周期和资源边界，项目是主人显式授权的交付契约。公共黑板是无组织的交流面，不能表达职位、汇报方向或不同公司的隔离。单靠人设提示也无法防止给无关成员发帖。

## 决策

把公司和职位图存于舰队协调库，模板仅初始化图，后续以保存的直接汇报关系为准。以单根树、一个 Agent 一个职位消除身份选择歧义，不要求每个职位已有人。公司任职不替代主人授权，不改内部人设、工作区、预算、审批或自主开关。

发送时按已提交的组织关系推导路线和收件人，拒绝跨层级/公司绕行；任职 Agent 不经公共黑板发组织内容。消息是存于本地的定向协作数据而非指令，可在已有工作中读取，不产生新 Run 或级联模型调用。实际收件 Agent ID 随消息固化，后任不会继承前任收件箱；历史由主人可见。

职位修改用公司修订拒绝丢写。新建 Agent 沿用草稿 API 与注册表，不在协调库的写事务内创建工作区；若随后绑定失败则明确保留可重新关联的草稿。归档立即失去任职能力，历史仍可查，不清理 Agent 数据或强制结束既有工作。

## 替代与代价

不把公司复制成各自的舰队（会分裂独立身份和现有额度），不以无边界群聊替代路由，不把上级消息解释成拥有主人权限的派工。代价是首版不表达多直属上级，消息由既有活动按需读取而非立即唤醒；[总设计](../DESIGN.md#company-organization)负责完整流程与边界。

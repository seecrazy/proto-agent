# ADR 0003：运行时协议、恢复认领与真实用量结算

> **决策记录，保留采纳理由。** 当前累计方案及实现边界已归并至 [PROTO 总设计](../DESIGN.md)；本记录不是另一份当前总设计，原决策状态保留。

- 状态：接受
- 日期：2026-11-21

## 背景

M61 后的实现保留了三类跨层缺口：模型非结构化输出可被解释成完成；拒绝记录未终结检查点；LLM 返回后超出估算的真实用量可能被预算拒扣。工作区对象与工具注册闭包也存在多份运行时引用。

## 决策

1. 模型输出是需要验证的协议输入，只有显式布尔 done=true 可以宣告执行者完成。解析失败走纠正观察，不转成完成。
2. 审批决定与检查点联合构成恢复依据。批准必须为 granted；执行副作用前先持久认领、移除等待令牌。认领后崩溃不自动重放，宁可要求人工核对，不冒充 exactly-once。
3. 所有任务链的 LLM 与工具调用继承同一来源预算池。预算守卫负责预留和结算；已经实际发生的用量不可因超额而“拒绝记账”。负余额表示实际欠额，不是合法的负消耗输入。
4. 工作区切换必须同时更新工具注册表和 Router 的工作区引用，不维护独立的新旧有效工作区。
5. 工具族的枚举读取、重定向等间接路径与直接路径遵循相同边界。

## 后果

- 可在不引入新依赖或持久 Schema 迁移的情况下修复授权和计账契约。
- 非法模型输出可能用尽步骤而失败，不再产生“看似成功”的容错。
- 外部调用已花费的 token 可能使余量短暂为负；下一次调用被拒绝。请求级硬限制仍需服务端输出上限与实时用量支持。
- 恢复认领并非分布式事务；多进程和完整 Agentic 观察历史恢复另行设计。

# ADR 0001：工具能力策略与持久化运行时

- 状态：接受
- 日期：2026-11-18

## 背景

当前 Agentic 循环允许 LLM 输出 `category`。Router 只对 `write_file` 使用该级别，其他工具直接执行。这导致模型可以通过输出 `read_draft` 绕过审批。审批队列、预算和自动白名单又仅存在于内存，重启后暂停任务无法恢复。

## 决策

1. **工具能力由工具注册表声明，不由模型声明。** 模型提供的类别只能加严，不能降级。
2. **所有有副作用工具使用同一授权管线。** 需要人工批准时，将待执行步骤写入持久检查点；批准后执行原步骤。
3. **运行时治理状态持久化。** 审批、预算和自动白名单使用 `DocumentStore`；文件后端以 0600 原子写入。
4. **执行默认失败关闭。** 仅使用平台隔离后端执行任意代码；无隔离后端时必须显式选择不安全模式。
5. **审计使用 keyed MAC。** 新审计记录用 owner secret 的 HMAC-SHA256；验证缓存绑定存储修订号。

## 后果

- 优点：权限边界不再依赖模型自觉；暂停任务可跨重启；重启无法重置配额。
- 代价：工具注册需要声明能力；本地无 gVisor/sandbox-exec 时默认不能执行任意代码。
- 迁移：旧无签名审计记录按 SHA-256 规则验证；新记录带 `algorithm` 字段。

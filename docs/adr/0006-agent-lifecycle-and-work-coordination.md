# ADR 0006：Agent 生命周期、持久调度与项目协作

- 状态：接受，M65–M67 已在本地实现
- 日期：2026-11-21
- 方案与验收：[总设计第 12 节](../DESIGN.md#fleet-next)

## 背景

M64 有独立 Agent 状态、GoalTree、黑板和可续接的执行会话；但新建与收编接线不一，顺序心跳可能拖延其他成员，目标层级没有表示前置依赖，黑板文字没有表达归属或验收。需要保留单机架构与内核边界，让 Agent 既能独立工作，也能交接同一个项目。

## 决策

1. **人设不授予权限。** 分离版本化配置、持续成长和主人自治策略；新建/编辑/收编共享初始化与策略语义。执行保留身份快照但动态复核权限。
2. **目标、交付任务、执行尝试分责。** GoalTree 保持唯一目标源；项目 WorkItem 负责依赖、归属、验收和版本化交付；持久 Run 负责入队、认领和调度，复用 M63 ExecutionSession 及 Router 检查点。
3. **先保证一致性，再并发。** 入队和占用执行槽与模型长链分离；保留每 Agent 单写者，新增有界调度、共享额度和请求级预算票据。任务认领和结算需要原子更新，不以文件单次替换或租约超时证明可安全重放。
4. **项目共享的是产物，不是身份或权限。** 首版采用主人分派、工程师执行、评审员验收；只共享项目明确授权的产物版本，L1 依旧执行每次授权。黑板只负责交流。
5. **验收先看客观证据。** 确定性检查绑定提交版本，模型辅判语义质量；未确认的副作用仍留给核对，不提供 exactly-once 承诺。

M65 选择复用现有文档存储和 L1 权威：人设推荐与自治策略独立升级，参数所有权存于原状态，暂停存于原舰队注册表。创建默认未启用，旧实例兼容原授权；预算池不能替代自主/主人来源判别。仅建议使用现有目标和优先级，不另开执行或引入模型费用。权限收紧检查发生在下一次自主派发/工具启动，不承诺撤回已开始的效果。

Agent 登记 ID 和显示名称分离：延续现有注册表 ID 作为持久引用，不以名称寻址或重命名目录，也不因修改名称要求运行暂停。控制台改名只更新注册表的 `name`；详见[名称与 ID](../DESIGN.md#agent-display-name)。

批量暂停/恢复复用每成员的持久标记，按现有名单一次写入；不引入覆盖未来成员的全局模式。批量归档要求显式确认 ID 集合，逐成员复用闲置检查并报告部分结果，不抢占正在工作或对话的成员。注册表先记归档再尽力移动托管目录，避免跨目录事务造成成员失联或重启复活；收编源目录原地保留，已初始化的空舰队也是有效状态。见[舰队批量操作](../DESIGN.md#fleet-bulk-controls)。

M66 选择舰队根下的本地 SQLite：Run、认领顺序和舰队模型票据可短事务更新，不迁移 Agent 的 DocumentStore。用单实例执行器及原 per-Agent 写锁，不以等待时间作重派依据。舰队和 Agent 额度是串联闸门，不假称跨两种存储的事务；调用前两者均须成功，异常窗口宁可保守计费。M67 把分派、提交、快照和验收事务放在同库；项目首版只产出受限的 UTF-8 文本，由固定检查器验证，不把私有工作区、全局工具或可执行测试脚本暴露给项目参与者。

## 替代方案与后果

- 从发帖文本解析任务：缺少原子认领、依赖和统一完成语义，不采用。
- 用人设 prompt 模拟角色和授权，或共享所有成员记忆以方便接力：不能维持可信边界，不采用。
- 用 JSON 文件拼接队列、预算及交付状态：单文件替换无法覆盖跨记录认领与发布；不采用。也不迁移目标、审计或 M63 检查点到新编排框架，避免双重权威。
- 先开启无界并发或通用自由委派：会放大预算、恢复与权限问题；按 M65 身份控制 → M66 调度预算 → M67 固定协作与验收推进，保留单机范围。

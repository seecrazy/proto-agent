# ADR 0004：统一执行上下文、工具契约与持久执行会话

> 当前完整设计与本轮验收统一见 [总设计第 15.2 节](../DESIGN.md#roadmap)，本文件保留架构取舍理由。

- 状态：接受，已实现并通过 M63 回归
- 日期：2026-11-21

## 背景

当前 actor 未系统继承人设和验收，工具目录缺少参数定义；Router 的待批工具可以恢复，但外层模型循环的观察、剩余步数和原验收会丢失。直接增加 prompt 或把单步完成当作整链完成不能解决这些问题。

## 决策

1. **上下文与聊天表达分离。** 身份/主人约束共享，执行协议独立；验收、来源和工作区是固定会话输入。项目 AGENTS 限定作用域，深层规则读到后先重新决策，外部观察不提升为主人指令。
2. **工具描述与参数校验单一来源。** 注册表保存 JSON Schema 子集，内置显式、自定义保守推导；坏参数在审批和副作用前拒绝。schema 不替代内核、路径或命令授权。
3. **持久化外层执行会话，不用接力摘要冒充会话。** 记录决策事件、观察、trace、固定上下文、预算来源、步数和待批身份；恢复回原循环并运行原质量门。
4. **先记在途再调用，未知结果不重放。** Router completed 检查点可作为已执行证据，未确认结果进入 needs_reconciliation；不承诺外部副作用 exactly-once。
5. **锁和权限范围不扩大。** 同 Agent 会话串行，其他 Agent 不共享模型大锁；工作区变更和版本不匹配停止恢复，目标终态在步骤边界检查。旧非会话 Router 任务仍可恢复。
6. **保持当前模型接口。** 本轮继续 JSON 文本决策，不同时改供应商原生工具协议、共享 usage 或文件事务；这些需要独立证据和后续设计。
7. **可见审批入口汇合。** 任务续跑和提案批准/拒绝均恢复原会话；绑定检查点的工具提案不能误入旧自主草稿生成路径。页面保存最新待批身份并显示原始参数。

## 替代方案与后果

- 仅补 prompt：解决不了参数失败前已写 Scratch、审批重启丢上下文和单步冒充成功，因此不采用。
- 仅存工具 task：复用现有 Router，但无法保留原循环；保留其作为副作用检查点，与新会话分工。
- 直接切外部框架/原生供应商会话：扩大迁移和兼容范围，且不能消除本地权限及预算问题，本轮不采用。
- 整体会话文档便于零依赖存储和原子替换，但长链日志会增长，跨文档一致性仍受单实例文件后端限制；需要后续压缩/事务设计，而非声称已解决 D8/D9。

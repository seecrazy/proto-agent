# ADR 0018：工程技能按需加载，完成依据来自本机回执

- 状态：已采纳
- 实施契约：[总设计 §8.5](../DESIGN.md#engineering-skills-and-evidence)

## 背景

实际对话中，Agent 在未查 `swiftc` 或 `xcodebuild` 时先说无法本地验证，之后也承认没有查过。聊天入口没有执行工具，方法菜单也没有提供「在哪里、如何、用什么验证」的合规入口。这和本机没有装编译器是两回事。原 iOS 交付硬门能拒绝假完成，但不帮执行者找项目入口、区分 SDK 与模拟器、识别失败原因，也未覆盖普通显式构建/运行测试任务。

## 决定

1. 发布小型内置 `SKILL.md` 目录，工具描述供发现，`read_skill` 按 ID 加载单份，记录内容摘要哈希。技能是可复用工作法而非授权来源；项目指令和原有权限、验收、主人意图优先。暂不开任意目录扫描、技能脚本自动执行或无人审查的第三方安装。
2. `inspect_build` 通过同一个命令工具的白名单、PATH 与后端识别诊断当前工位的构建入口，区分能尝试、需审批、执行器不可用、尚未识别项目。无副作用和模型请求。纯聊天的本机能力问询只回报宿主检测，不把问句转成构建；实际 SDK、依赖、构建和测试通过仍需要 `run_command`。
3. 原 Router 统一执行，持久会话保存成功或失败的验证回执。新会话冻结明确要求的检查项，要求同工位的实际回执；跳过、展示版本、超时、退出失败、无隔离或命令后再次修改都不算。旧会话不追加验收项。iOS App 仍使用更严格的可执行产物及源码指纹，并兼容仅引用工位内工程的 Xcode workspace。发现缺证据时在同一工作片给一次补正机会，仍缺则标未验收，不靠新会话无限返工。
4. 不引入第二套 Shell/调度/权限系统。保留有界工作片、断点、可核对的审批与工作区、暂停时可答话的能力；将可重复做法和可验证的执行结果与模型、人设分离。

## 取舍

提示词和方法列表不能证明做过事；自动运行推断出来的构建则会执行项目脚本，不能用于只读聊天或探测。保留命令沙盒、既有权威入口和明示边界。首批提供本机非交互构建/测试，不宣称支持任意脚本终端、安装依赖、视觉/用户验收、签名上架或与其他工具完全等价。普通命令回执说明本次调用而非项目外部变化后的全量保证。

独立 pytest 样例实际暴露 macOS 沙盒对空设备的拒写；只允许向 `/dev/null` 写数据，而不是解除文件写限制或让用户禁用 pytest 日志。

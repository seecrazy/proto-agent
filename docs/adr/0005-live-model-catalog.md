# ADR 0005：持久模型目录与请求边界热切换

- 状态：接受，已实现并通过 M64 回归
- 日期：2026-11-21
- 当前设计与验收：[总设计第 14.4 节](../DESIGN.md#operations)

## 背景

现有启动流程只从环境创建一次主/快模型，Agent、规划器和归因器分别持有客户端。仅改环境变量或替换单个字段无法让整个舰队、离线实例及后续加载的 Agent 一致切换。

## 决策

1. 数据根保存版本化、0600 的模型目录和主/快选择；环境仅引导首次无目录启动。保存接入不自动选中。
2. 通过共享目录和稳定角色代理取代批量覆盖对象；每次调用固定客户端快照，在途完成、后续切换，不取消、不重放。
3. 短锁只保护配置、落盘和快照发布，不包围模型网络请求，不获取 Agent 的长操作锁；先持久化成功再发布，revision 防止表单覆盖。
4. Web 提供受令牌保护的新增/编辑、选择和重载；终端复用同一目录。不提供新协议代码动态加载、目录探测或后台付费探针。
5. API 与页面不回传密钥；端点 URL 不接受嵌入凭证。熔断按 Agent 和配置隔离，预算/审批/会话不随切换重置。

## 替代方案与边界

- 重启或覆盖 os.environ：不能满足不重启和请求边界一致性，不采用。
- 直接改 llm 字段：遗漏缓存、归因、规划、快模型和新 Agent，不采用。
- 等所有 Agent 停止再换：长任务使切换不可用，不采用。
- 本机 JSON 文件不是密钥保险箱；备份须保护，跨进程并发编辑和活跃进程共享目录仍受单实例边界约束。

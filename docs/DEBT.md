## D5 · run_python 沙盒 profile 仅覆盖 macOS sandbox-exec

- **现状**：Linux（runsc）路径存在，仓库虽有 Linux CI 配置但未安装 runsc，本轮也未实测 Linux 隔离；sandbox-exec profile 对新工具链（如 swift concurrent runtime 的 aux 进程）可能过紧。更高风险的宿主读取边界见 D12。
- **触发条件**：换机器/换工具链。
- **风险**：低（单机产品当前明确 macOS）。
- **建议时机**：Linux 部署需求出现时。
- **登记**：M36 期。

## D6 · 一次"编辑丢失"事故与测试过弱的耦合（已即时修复，留档警示）

- **事故**：M50 的 server _api 重写在一次脚本编辑中只打印了预览、未写盘（后续小编辑基于旧底子写入）；M50 测试持的是 manager 新锁而旧 server 用全局锁——全局锁在测试中空闲，测试全绿但未覆盖真实路径。用户要求新功能时复查代码才发现。
- **修复**：重写 _api（快通道集合+per-agent 锁真正落地）；测试加固为同时占住 server 真正会用的锁（全局+per-agent），旧实现必 409。
- **教训（规则化）**：①脚本改文件必须 open().write() 收尾，打印预览的脚本和写入脚本不得混用；②并发/锁类测试必须占住"被测实现实际获取的锁"，否则是假阴性绿灯；③涉及"哪个实现用哪把锁"的断言，用源码级断言兜底。

## D7 · 会话恢复已落地，未知效果核对与取消未闭环

- **触发条件**：观察—行动链在某个工具审批处暂停后恢复，或执行中进程重启。
- **已偿还部分（M63，2026-11-21）**：新 `execution_sessions` 保存固定上下文、项目指令、验收、预算来源、完整工具事件、观察/trace 和剩余步数；任务 API 与控制台审批回原循环，重复恢复不重放。Router completed 可接纳，未知在途转 needs_reconciliation；同目标待批不另起链，丢弃在步骤边界/模型返回后阻止新动作。70 项新增回归覆盖重启、并发双恢复、拒绝、严格布尔审批和原验收。
- **现状/风险**：旧无会话 Router 任务仍只恢复原步骤；没有自动核对未知外部效果或完整会话管理界面，没有贯穿外部进程的取消/终止协议。会话、预算、奖励与审批落盘不是跨文档事务；进程已执行但结果未知时只能阻塞并人工核对，不能宣称 exactly-once 或“丢弃即撤回”。
- **方案**：在现有持久会话之上补安全的核对证据/人工解锁流程、会话枚举管理、取消令牌与工具终止协议；与 D8/D9 的事务及结算设计协同，不能简单重置 pending 后重跑。
- **建议时机**：后续运行时专项，优先级高；本债务部分偿还，不能整体关闭。M63 设计和边界统一见总设计第 7、11、15.2 节。

## D8 · 文件存储不是跨实例事务，路径与缓存失效仍需专项加固

- **触发条件**：同进程不同 FileSystemStore 实例或不同进程同时操作同一数据目录；外部程序修改存储文件；工作区路径被并发替换。
- **现状/风险**：实例锁只保护单个对象；临时文件名仅含 PID；读改写不是事务。`find/revision` 的 collection 路径未统一校验，revision 只取数量/最大 mtime，不能视为抗对抗篡改的修订令牌。文件工具 resolve 后再打开仍有 TOCTOU 窗口。
- **方案**：唯一临时文件、统一根目录/符号链接校验、目录句柄相对打开；进程间锁或 SQLite 事务；更可靠的存储修订令牌。不要用审计 reseal 代替并发事务。
- **建议时机**：共享数据目录或对抗性执行之前，优先级高。当前以单实例单写者运行，不扩大多进程保证。

## D9 · 共享 LLM 客户端的 usage 是可变属性

- **触发条件**：多个 Agent 并行使用同一 LLMClient，调用返回与读取 `last_usage` 之间发生另一线程写入。
- **现状/风险**：M62 修复了单调用漏计与错误池，但共享客户端属性不等于请求级 usage，仍可能串账；跨日长调用的结算也尚未绑定原预留周期。
- **方案**：让调用返回文本与 usage 的不可变响应对象，或线程/调用局部遥测；预留票据绑定周期，结算时核对。
- **建议时机**：下一轮预算/并发专项，优先级高；不要为解决遥测串账退回全舰队串行。

## D10 · 包元数据与 LICENSE 不一致

- **触发条件**：构建/发布 Python 包或用户按元数据判断授权。
- **现状/风险**：`pyproject.toml` 写 MIT，仓库 `LICENSE` 文本为 GNU AGPL v3；本轮不擅自修改授权文件或推断权利人意图。
- **方案**：请权利人确认唯一授权来源，再同步包元数据与说明。
- **建议时机**：发布前必须处理。

## D11 · 独立质量门尚非确定性验收器

- **触发条件**：验收要求复杂行为，证据过长被截断，或验证模型误判。
- **现状/风险**：已隔离执行者叙述、读取最终文件并校验返回结构，但 pass 仍来自 LLM，不是自动重跑测试或按预定义断言验收；脚本化 LLM 回归证明接线，不证明真实模型质量。
- **方案**：结构化本机验收项（文件/命令/退出码/断言）+ 确定性验证优先，语义质量交 LLM 辅判。
- **建议时机**：推进无人值守产品交付前。

## D12 · macOS 执行 profile 不是完整主机读取隔离

- **触发条件**：自动执行的代码主动读取宿主其他目录或持久后台进程与文件工具竞争。
- **现状/风险**：profile 基于 allow default，只限制写入/网络并显式拒读部分 PROTO 内部路径；没有禁止读取所有用户秘密，也没有容器级后台进程/资源生命周期管理。不能将 WORKSPACE_WRITE 标签解释为“进程只能读取工作区”。
- **方案**：定义可读系统/工具链白名单与用户目录拒读策略，补真实沙盒探针；或采用具有完整文件系统隔离的后端。强对抗代码在完成专项前应禁用本地执行（`PROTO_EXEC_BACKEND=none`）。
- **建议时机**：引入不可信代码或无人值守外部代码运行之前，优先级最高；Linux runsc 实证同时推进（见 D5）。

## D13 · L5 治理元件不等于可信、自激活的进化闭环

- **触发条件**：把晋升 default 理解为运行时代码已替换；候选变体尝试迎合/篡改评测；影子任务为空或候选缺少指标。
- **现状/风险**：`EvolutionEngine.promote` 更新档案状态，ProtoAgent 并没有加载它替换当前执行器。`Sandbox` 将输入与 expected 一起写入候选可读的 cases.json，runner 也在同一可写目录输出布尔判定，不能视为对抗性评测。`ShadowRunner` 跳过候选缺失的指标，空集也可生成 clean 报告；底层人工确认方法本身不替代 OWNER 认证。
- **方案**：输入与期望隔离、宿主侧验证原始输出、完整且非空的评测覆盖、签名报告绑定候选/测试集/版本；先完成这些证据门，再设计运行时加载与回滚，不自动热替换 L1。
- **建议时机**：声称生产自进化或允许不可信候选执行之前，优先级最高；本轮不为“补全功能”绕过这些治理门。

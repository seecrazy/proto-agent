> 存在理由（2026-11-19 盲人摸象复盘）：布局形态散在 CSS/DOM/JS/存储十几处，
> 没有整图时每次改动只能看见"点"，看不见引用线与整体面。
> **规则：任何 UI 改动，先更新总设计 UI 章节的对应区域与邻接清单，再动代码。**

## 布局不变量（改动后逐条自检）

- I1 每个类别页签全屏恰好出现一次（当前：4 类别 4 页签）
- I2 每个控件贴附其控制对象（把手贴自己的栏；跳转目标在跳转时可见）
- I3 任何交互只影响其声明的作用域（点左栏不改变右栏，反之亦然）
- I4 全部状态（栏类别/收起/卡片折叠/视角）刷新恢复
- I5 伙伴视角无工程信息（tech 卡片与页签隐藏）
- I6 左=观察右=干预的静态分区不因局部改动松动

## 改动流程（任何 UI 变更必走）

1. **先改总设计 UI 章节**：画出改后的整图（哪怕手绘 ASCII）；
2. **邻接清单**：列出被移动/新增元素的每一处引用（把手/锚点/徽标/
   localStorage/JS id/CSS 选择器）——逐项确认随动；
3. 实现；
4. **完形目检**（先于功能测试）：整屏截图，回答四个问题——
   有无重复的控件？有无位置不合惯例的控件？这个布局是连贯的一个设计吗？
   用户的一句话意图在这个画面上成立吗？
5. 功能测试 + 源级不变量测试（tests/test_ui_invariants.py）。

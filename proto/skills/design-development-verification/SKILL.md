# 设计 → 开发 → 验证

1. 读本工位的项目指令、README、现有实现和固定验收。目标有歧义时先写下假设与非目标。已立项的设计变更先落到设计文档/ADR；小修复先找复现和根因，不写空泛方案。
2. 选一个最小可运行切片，沿用现有技术栈和文件位置。用 `read_file` / `grep` 定位，并用 `edit_file` 精确修改；加一个能在旧行为下失败的回归。代码留在工位，不贴在聊天里冒充产物。
3. 用 `inspect_build` 查真实构建入口和本机检查命令。先跑最贴近改动的检查，再跑必要的构建或回归；读退出码与第一条实际错误，改根因，再跑原命令。先证明卡点再求助；只把确实依赖外部的部分留给主人。
4. 汇报变更路径、运行的命令与结果、未覆盖的验收、接续动作。编译、启动、功能、用户价值和发布是不同的证据；一个通过不替代另一个。恢复时先读上一回执与当前工位，不重复已完成且仍适用的操作。
